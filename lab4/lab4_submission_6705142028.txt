# ========================================
TASK 3: GET VS POST
# ========================================

--- TASK 3 ---

GET output:

Method received: GET
Query string: course=192-442&week=4

POST output:

Method received: POST
Query string:
POST body: name=student&id=123

Log evidence:

::1 - - [03/Oct/2026:12:33:50 +0000] "GET /cgi-bin/echo.sh?course=192-442&week=4 HTTP/1.1" 200 270 "-" "curl/8.5.0"
::1 - - [03/Oct/2026:12:33:50 +0000] "POST /cgi-bin/echo.sh HTTP/1.1" 200 281 "-" "curl/8.5.0"

Explanation:

GET carries data in the URL query string, so the data is visible in
the URL and is recorded in the access log.

POST carries data in the request body, so the data is not shown in
the URL or in the normal Apache access-log request line.

This matters because GET data can be visible in the URL, browser
history, bookmarks, and access logs.

Security Question:

If a password were sent using GET, two places where it could appear
are browser history and Apache access logs.
